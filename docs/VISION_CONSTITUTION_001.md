**Core Purpose:** Defines the unalterable vision, spatial scope, temporal mechanics, and experience principles for the World Trade Center Reconstruction.  

---

## 1. THE MOST IMPORTANT CORRECTION

This project is **NOT** primarily:
- A database project
- A Neo4j project
- A PostgreSQL project
- An API project
- A dashboard project
- A data archive
- A static timeline viewer
- A traditional enterprise digital twin

Those are supporting technologies. They are not the vision.

---

## 2. PROJECT IDENTITY

The project is an **explorable historical reconstruction of the entire World Trade Center Complex across time (1966–2001)**.

Visitors do not simply view history. **Visitors inhabit history.**

They can walk through it, experience it, observe it evolve, and return the next day to find that time has moved on.

---

## 4. TEMPORAL MECHANICS: THE 35-DAY CHRONOLOGY

The project exists across **1966–2001**. The defining temporal feature is:

$$\text{1 Real-World Day} = \text{1 Historical Year}$$

- **Day 1:** 1966 (Groundbreaking & Slurry Wall Slurry Excavation)
- **Day 2:** 1967 (Bedrock Excavation & Foundation Placement)
- **Day 3:** 1968 (Structural Core Column Erection)
- **...**
- **Day 8:** 1973 (Official Dedication Ceremony)
- **Day 11:** 1976 (Observatory & Windows on the World Opening)
- **Day 28:** 1993 (Post-1993 Sub-grade Infrastructure Upgrades)
- **Day 35:** 2001 (The Complete Operational Complex)

The world evolves continuously. Visitors return tomorrow and discover that history has advanced. Visitors inhabit a living chronology.

---

## 5. PRIMARY VISITOR EXPERIENCE

Visitors should:
- Walk the 16-acre site freely
- Watch construction occur in real time
- Observe buildings rise floor-by-floor
- See infrastructure systems installed
- Enter active construction zones
- Visit engineering offices, drafting trailers, and drawing rooms
- Explore finished buildings and public spaces
- Observe operational HVAC, electrical, and transit systems
- Witness the 35-year evolution of the complex

This is an **experience**. Not a dashboard.

---

## 6. DRAWING ROOMS & ENGINEERING PROVENANCE

Drawing rooms are a core experience. Visitors can enter:
- Engineering offices
- Drafting rooms
- Project trailers
- Planning spaces

They can physically inspect drawings, schedules, revisions, and engineering decisions. The project communicates **how** the complex was built, not merely **what** was built.

### The Provenance Principle:
Every meaningful object in the world is evidence-aware. When a visitor touches a beam, column, equipment, room, drawing, or wall, the system answers:
1. *What is this?*
2. *Why is it here?*
3. *Where did this information come from?*
4. *What evidence and original Port Authority drawings support it?*
5. *What historical role did it serve?*

Nothing exists without a reason.

## 7. IMMERSION PRINCIPLE

The project should feel like:
- A living historical world
- A museum visitors can walk through
- A reconstruction visitors can inhabit

The project should **NOT** feel like:
- An enterprise dashboard
- A database frontend
- A graph viewer

---

## 8. TECHNOLOGY ROLE

Neo4j, PostgreSQL, PostGIS, FastAPI, React, React Three Fiber, Three.js, APIs, Schemas, and Graphs **all exist solely to support the experience**.

- **The experience is primary.**
- **Technology is secondary.**

---

## 9. THE DESIGN TEST

Every proposed feature, code edit, or architecture decision must answer:

> *"Does this help visitors experience the World Trade Center Complex through time?"*

- If **YES**: Prioritize it.
- If **NO**: Deprioritize it.
